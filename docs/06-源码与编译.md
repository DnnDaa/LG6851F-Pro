## 编译环境与步骤

使用区分大小写的Linux文件系统。Windows用户先将源码tar归档解到WSL的Linux目录；不要直接在 `/mnt/e` 或大小写不敏感NTFS里编译。

```sh
mkdir -p ~/lg6851f-public
tar --zstd -xf /path/lg6851f-public-source-20261015.tar.zst -C ~/lg6851f-public
cd ~/lg6851f-public/repository
```

安装OpenWrt构建依赖，参考 [OpenWrt构建环境](https://openwrt.org/docs/guide-developer/toolchain/install-buildsystem)。还需zstd、squashfs-tools、OpenSSL；SDK签名脚本使用的Python依赖以 `lg6851f_sign_tool` 中脚本为准，通常需要兼容Python3.10及pycryptodome/pyasn1等。源码不附私人Python虚拟环境。

```sh
JOBS=4 ./scripts/build-public.sh
```

入口会把固定的feed快照接到本地，执行OpenWrt构建，按当前端口配方重编原厂模块、CPU/LED模块，再组装rootfs和A签名包。第一次构建需要下载工具链及上游源码，固定feed并不代表完全离线。日志和生成的APK私钥不进入Git。

此次整理核对了源码、运行文件、既有模块哈希和入口语法，**没有在此公开目录完成新的全量干净编译**。构建入口是当前已用构建步骤的便携化整理，使用者应保留完整日志；不能把随包已签名镜像与新环境字节相同作为既成结论。`build-config/source-integration.json` 记录该边界。

代码默认设备仍是6.18.44。不要把其他内核的ko或APK拷入最新固件。历史原生流程可能同时导出B包，但这次原厂驱动运行链只支持A；公开发布与使用只取A成品。

## 签名材料

`lg6851f_sign_tool` 中保留的MTK **hsm_test_keys** 是既有公开项目使用的测试签名链，整理时逐个与公开来源比对字节和SHA256；不是设备SSH私钥、APK私人签名密钥或厂商生产密钥。公开来源与校验见源集审计记录。不能把这些已公开测试材料误称为个人私钥，也不能将生产密钥补入仓库。

APK私钥在首次准备环境时本地生成，`private-key.pem` 已忽略。只发布对应公钥；自己的订阅、生成的短信引导文件、设备校准和NV备份均放仓库外。

## 来源与旧资料

原资料包括2026-08/09的OpenWrt适配手册、完整源码归档与FG370 SDK，后来本项目移植了原厂驱动、硬件加速、CPU频率和新管理页。旧文档中的“mt76路线、WED关闭、CPUFreq尚无policy”等描述是旧阶段记录，不是本版行为。私人维修原文含账号和设备信息，因此不整份公开；工程改动通过当前源码和构建记录交付。
