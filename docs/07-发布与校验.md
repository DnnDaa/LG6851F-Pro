# 7. 手动发布到自己的 GitHub

本次只在本地生成文件，未登录或写入任何GitHub仓库。

## 目录上传位置

| 本地内容 | GitHub位置 |
|---|---|
| repository目录内的源码、docs、tools、README | 仓库main分支 |
| release-assets内固件、工具、源码归档、SHA256清单 | 同一版本的Release附件 |
| 私有备份、短信引导生成目录、个人签名密钥 | 不上传 |

GitHub普通Git单文件上限100MiB，网页上传单文件上限25MiB；因此本版固件即便能通过Git提交，也不适合网页直接上传到代码列表。源码归档与工具也放Release，保留清晰的下载入口。参见 [GitHub大文件说明](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github) 和 [Release说明](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)。

新建空仓库后，进入 `repository` 目录，检查 .gitignore 与扫描记录，再按自己的仓库地址提交；不要在包含私人备份的父目录执行git add。

```sh
git init -b main
git add .
git diff --cached --stat
git diff --cached --check
git commit -m "Add LG6851F Pro public firmware source and SMS-to-OpenWrt guide"
git remote add origin https://github.com/YOUR_OWNER/YOUR_REPOSITORY.git
git push -u origin main
```

如果是已有仓库，先备份/分支并审阅差异，不能照抄git init后强推；本整理没有替你修改已有Git历史。发布tag建议为 `lg6851f-public-20261015`，附件统一取本次 `release-assets`，Release正文可直接参考旁边的 `RELEASE_NOTES.md`。上传后把README的下载入口指向自己的Release。

Linux校验：

```sh
sha256sum -c SHA256SUMS.txt
```

Windows单个校验：

```powershell
Get-FileHash .\lg6851f-a-public-20261015-sysupgrade.tar.gz -Algorithm SHA256
```

源码归档保留权限和符号链接；由Windows网页逐个上传源码时可能丢失它们，推荐Git在Linux中提交或让使用者下载源码归档。
