# V2.10 源码与精确重打包

本版来自 systemfix-94 / Linux 6.18.44 旧分支。没有采用取消的主线实验；没有从零全量重编全部厂商组件。

源码归档保存仓库工程、后续 C/头文件修补、完整 native hostapd 源码及配置、当前 HNAT 和 nf_nat 源码、TurboACC、A/B 槽差异和精确公开运行层。`development-history/V2.10/` 为本轮整理入口，`development-history/systemfix-source/` 为按内部版本保留的源码；其中历史基线和试验文件仅供追溯，不应全部依次覆盖。实际模块身份以两槽 manifest 和 `release-runtime/public-b-assembled-root.tar` 为准。

源码 Release 附件额外包含：

- `release-runtime/public-b-assembled-root.tar`：公开 B 槽完整运行层，Linux 权限和符号链接保留。
- `files-slots/a/`、`files-slots/b/`：同一代码基线的槽位差异，包含无线启动门禁、健康确认、升级器和版本字段。
- `release-runtime/boot_a.img`、`boot_b.img`：相同内核载荷的已验证签名启动镜像。
- `release-runtime/connsys_gnss.img`、scatter 和 download_agent：对应 MTK 打包输入。
- `release-runtime/public-a-rootfs.squashfs`、`public-b-rootfs.squashfs`：本轮全回读核对后的精确根镜像。

## 重打包

在 Linux 解压源码归档后运行：

```sh
python3 scripts/repack-V2.10.py --out ./bin/V2.10-repacked
```

该入口仅使用已验证的镜像构造 A/B 网页包和 MTK 包，不写设备，不重新签名或编译，生成自己的包级 SHA256 清单。源镜像哈希必须与 `build-config/V2.10-runtime-inputs.json` 一致。gzip/ZIP 元数据不同可能使重打包文件总哈希不同，但三份内部镜像应完全一致。只克隆 Git 仓库时需从 V2.10 的源码附件补充 `release-runtime/`，不要将自用 rootfs 或另一台设备校准填入该目录。

## 后续修改/重编译

`files/` 保存公开适配层，默认槽位 B；不要将其与 A 槽 boot 直接混用。改动需要同步相应槽位门禁、boot-control retry 字节、升级器分区校验、CONTROL 和 scatter，而非只改名字。历史 `scripts/build-public.sh` 路线留作 v1.0.2 的构建参考，不能未经适配就当成 V2.10 精确重建入口。

内核及厂商无线模块必须严格匹配实际 6.18.44 配置/导出 ABI。当前 Wi-Fi 的完整基线编译后还包含有记录的有界解析/PMKSA/雷达索引及 APCLI 入口修补；`wifi-rebuild/` 保留清理重编与重定位脚本。不能把通用原厂 SDK 的同名模块直接替换当前 `mt_wifi.ko`。HNAT 的统计合并与有界硬件轮询不应改成关闭加速，nf_nat 默认模式为 0，CAKE 保留按需 tin 与初始化修正。

本轮没有执行从下载依赖到全量重编/冷启动的完整流水线。新代码重编后必须重新进行模块/签名、完整根层、APK 元数据、两包同镜像、槽位边界及实机验收；不能把本版既有测试自动移用到新二进制上。

所有设备校准、SSH 主机密钥、用户密码、订阅和维修日志都不属于公开源码输入。A 槽保留原厂时使用 B 包；本仓库/重打包操作不会触碰实机共享 SSH 文件。
